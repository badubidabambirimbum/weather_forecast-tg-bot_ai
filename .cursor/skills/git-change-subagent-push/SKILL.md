# Git change: субагент + git-change-analysis-push

## Назначение

Основной агент **не выполняет** длинную цепочку `git` сам, а запускает **Task**-субагента, который **обязан** прочитать и следовать проектному skill:

- `.cursor/skills/git-change-analysis-push/SKILL.md`

Так изолируются команды в отдельном контексте и снижается риск пропустить шаги workflow (тематические коммиты, тесты, guardrails).

## Когда включать

- Пользователь просит: «запусти субагента и запушь», «делегируй push», «пусть отдельный агент сделает commit по skill».
- Пользователь указывает этот skill по имени или пути.

## Инструкции для основного агента (родителя)

1. Убедись, что рабочая директория — корень репозитория с файлом `.cursor/skills/git-change-analysis-push/SKILL.md`.
2. Запусти инструмент **Task** с параметрами:
   - `subagent_type`: **`shell`** (специализация на командах и git);
   - `readonly`: **`false`** (нужны `git add` / `git commit` / `git push`);
   - `run_in_background`: **`false`**, если пользователю нужен сразу итог в этом чате.
3. В поле **`prompt`** передай **дословно** блок из раздела [Промпт для субагента](#промпт-для-субагента) ниже (при необходимости добавь 1–2 строки контекста от пользователя: исключить файлы, только анализ без push и т.д.).
4. Дождись финального сообщения субагента и **кратко** перескажи пользователю: ветка, список коммитов, результат `git push`, остаток `git status`.

## Промпт для субагента

Скопируй целиком в `prompt` вызова Task:

```text
Ты субагент в репозитории проекта Weather Telegram Mini App. Рабочий каталог — корень git-репозитория.

Шаг 1. Прочитай целиком файл (используй инструмент чтения файлов):
.cursor/skills/git-change-analysis-push/SKILL.md

Шаг 2. Строго выполни workflow из этого skill: сбор контекста (git status, git diff, staged, log), разбиение на тематические коммиты при необходимости, сообщения коммитов на русском в формате conventional commits из skill, проверки перед push, git push. По умолчанию включи в коммиты все изменения рабочего дерева, кроме секретов; не коммить .env и файлы с токенами.

Шаг 3. Учти локальные хуки Cursor (если есть): перед commit/push может выполняться .cursor/hooks/git_policy.py — сообщения коммитов должны соответствовать ожидаемому формату, тесты должны проходить.

Шаг 4. Итог выведи в формате «Шаблон результата» из git-change-analysis-push/SKILL.md и приложи последние строки git log --oneline -n 5 и git status --short.
```

## Ограничения

- Субагент **не заменяет** явный запрет пользователя на push или на опасные git-команды из `.cursor/rules/git-safety.mdc`.
- Если пользователь просит **только анализ** без отправки в remote — в конце промпта добавь строку: «Выполни анализ и коммиты по необходимости, **git push не выполняй** без отдельного подтверждения пользователя в родительском чате.»

## Связь со skills

- Источник истины по шагам и сообщениям: **`git-change-analysis-push`**.
- Этот skill (**`git-change-subagent-push`**) отвечает только за **механику делегирования** через Task.
